# Проверки перед первым релизом

Первый релиз выпускается после ревью и слияния PR. Unit-тесты используют синтетические
ответы и проверяют поведение пакета, а не доступность функций живого API.

Автоматическая проверка: 91 тест, 603 проверки; Composer validate и PHP lint проходят.
Десять тестов из `SecondReviewTest` также запускались на исходном коде до правок
и воспроизвели прежние дефекты.

## Результаты разбора ревью

| № | Решение и границы проверки |
|---|---|
| 1 | MAX передаёт `secret` при подписке, валидирует 5–256 символов. Контроллер сверяет переданное приложением значение `X-Max-Bot-Api-Secret`. Подмена/отсутствие секрета не запускает обработчик. Автоматическое удаление старых подписок не предполагается: смена URL требует явного управления подписками. |
| 2 | `chat.denied` – эмпирически известный код. `bot.blocked`, `user.blocked`, `chat.blocked` – неподтверждённые предположения совместимости, а не документированные гарантии. `too.many.requests` также не гарантирован справочником; HTTP 429 обрабатывается независимо. Тесты классификации синтетические. |
| 3 | Пустой callback остаётся локальным no-op. Это не успешный ответ сервера на `/answers`. Проверка отсутствия зависшего индикатора в клиентах MAX остаётся открытой. |
| 4 | Чтение polling повторяется при сетевых ошибках, 5xx, некорректном JSON и rate limit. Бюджет общий: до трёх повторов с неизменным курсором. Обычные отказы API и ошибки конфигурации не повторяются. |
| 5 | `exchange()` сохраняет безопасные классификации клиента и пишет причину/HTTP-статус. Произвольные исключения и неизвестные reason очищаются, чтобы подменяемый клиент не раскрыл URL или токен. |
| 6 | MAX проверяет форму вложений до PUT. Фото/документы сохраняются по токену; поля ответа `photo_id` и `url` не отправляются обратно. Неизвестное медиа или отсутствующий токен дают явный отказ до изменения сообщения. |
| 7 | Ошибка конфигурации Telegram при `getFile` превращается в постоянную `DownloadException`. Исправление конфигурации обязательно перед повтором. |
| 8 | Битые Telegram ID пропускаются при наличии валидного ID для продвижения. Если offset вычислить нельзя, остаётся явная `invalid_update_id`; произвольный offset мог бы потерять события. MAX может пропустить битый элемент благодаря отдельному marker. |
| 9 | Отсутствующая локаль MAX остаётся пустой и описана в README. Поле TamTam `user_locale` не принимается за гарантированное поле MAX. |
| 10 | 300/304 и редиректы без Location классифицируются как временный `invalid_redirect`. Существующий Location с запрещённым адресом по-прежнему отклоняется как небезопасный URL. |
| 11 | Сохранён явно заданный контракт `fallbackWhenBlocked = true`: права на медиа и текст могут различаться. `false` запрещает второй запрос. `blocked` обозначает запрет доставки, а не доказательство того, что пользователь остановил бота. |
| 12 | Лог отказа multipart Telegram содержит форму текстовых полей, клавиатуры и размер файла; ни содержимое файла, ни текст подписи не выводятся. |
| 13 | cURL 60: `tls_untrusted_ca`, 77: `tls_ca_file`, 58: `tls_client_certificate`. Используется доступная в PHP константа `CURLE_SSL_CACERT` для кода 60. |
| 14 | Unit-тесты cURL остаются подменой границы. Добавлен отдельный `scripts/curl-smoke.php`, который передаёт вызовы настоящему libcurl и сверяет IP соединения с закреплённым IP при нерабочем прокси в окружении. |
| 15 | `bot_started` без пригодного timestamp отклоняется как malformed. Валидные старты используют timestamp вместе с chat/user ID; случайные ID не создаются, чтобы повторная доставка дедуплицировалась. |

28.09.2026 `php scripts/curl-smoke.php` прошёл на `fu.oneme.ru` и `iu.oneme.ru`:
TLS проверен системным набором CA, IP соединения совпал с закреплённым, переменные
прокси не повлияли. Корневые URL ответили HTTP 404. Это проверка транспорта без
авторизации, не загрузка/скачивание настоящего вложения и не проверка всех окружений.

## Живая приёмка с отдельными тестовыми ботами

Все пункты ниже пока не выполнены. Нужны токены и тестовые чаты; секреты не сохраняются
в отчёте и не передаются в аргументах команд.

- [ ] MAX: зарегистрировать URL без секрета в пути, убедиться в доставке заголовка
  `X-Max-Bot-Api-Secret`; неверный/отсутствующий заголовок не вызывает обработчик.
- [ ] MAX: проверить список подписок до и после повторной регистрации того же URL,
  затем нового URL. Зафиксировать, остаётся ли старый URL. Удалить тестовые подписки.
- [ ] MAX: остановить бота, проверить фактический код отказа и `blocked`; при
  `fallbackWhenBlocked: false` второго запроса нет. После возобновления отправка работает.
- [ ] MAX: нажать callback без notification в мобильном и настольном клиентах, проверить
  индикатор ожидания и переход к следующему сообщению. Отдельно проверить уведомление
  с непустым текстом. Записать версии клиентов.
- [ ] MAX: отправить фото и PDF с клавиатурой, изменить подпись и удалить/заменить
  кнопки; файл должен сохраниться и открываться после изменения.
- [ ] MAX: проверить загрузку PDF, `attachment.not.ready` и повтор `sendFileId()` с
  сохранённым токеном. Фиксировать только классификацию, без самого токена.
- [ ] Обе платформы: скачать присланные фото и документ, проверить реальные байты;
  для Telegram повторить через настроенный прокси с поддержкой `/file/`.
- [ ] Telegram: различить закрытый личный чат и группу без прав на медиа, проверить
  обе политики fallback. Не считать медиа-403 доказательством блокировки пользователем.
- [ ] Telegram: остановить и вернуть бота в личном чате, проверить `my_chat_member` со
  статусами `kicked`/`member` и `membership` `stopped`/`started`; при первом `/start`
  `my_chat_member` не приходит.
- [ ] MAX: остановить и вернуть бота, сверить фактическую форму `bot_stopped`
  (`chat_id`, `user`, `timestamp`) – сейчас она повторяет `bot_started` без живой проверки.
- [ ] MAX: прислать голосовое сообщение и зафиксировать тип вложения (ожидается `audio`,
  отдельного `voice` в справочнике нет).
- [ ] MAX: подписка с `bot_stopped` принимается (`POST /subscriptions` и опрос с `types`):
  тип есть в справочнике, но живьём не проверен.
- [ ] MAX: `deleteWebhook($url)` снимает только указанную подписку, остальные остаются;
  повтор при уже снятой – без ошибки.
- [ ] Telegram: `deleteWebhook($url)` при вебхуке другого адреса его не снимает, а свой
  снимает – в том числе адрес с query (сравнение строгое, нормализацию адреса Telegram
  живьём не проверяли).
- [ ] При естественном throttling проверить статус и задержку. Не создавать нагрузку
  на API ради получения 429.

## Дополнительное ревью: сохранение текста и медиа

1. Потеря длинного текста с коротким `fallbackText` воспроизведена тестом до правки.
   Выбран вариант без автоматической отправки двух сообщений: `caption_too_long`
   отправляет весь исходный текст с клавиатурой, игнорируя `fallbackText`; медиа
   пропускается. Текст сверх лимита обычного сообщения вызывает ошибку до сети.
   Проверены 1360 единиц, границы 1024/1026 с эмодзи и отсутствие повтора при отказе
   отправки текста. Для остальных причин отказа `fallbackText` остаётся полной заменой
   текста; пример README исправлен соответственно.
2. Удаление медиа при MAX `editMessage()` по умолчанию воспроизведено тестом до правки.
   Теперь сначала выполняется GET; медиа/неизвестное вложение без `isCaption` вызывает
   `caption_required`, PUT не выполняется. У текстового сообщения клавиатура по-прежнему
   удаляется или заменяется. Ошибка GET и повреждённый ответ останавливают редактирование.
   GET/PUT не атомарны; параллельные изменения одного сообщения сериализует приложение.
