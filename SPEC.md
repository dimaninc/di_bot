# Пакет `dimaninc/di_bot`

Транспортный слой для ботов Telegram и MAX, распространяемый как пакет Composer.
Контракт реализованной версии описан в [README.md](README.md).

## 1. Назначение

Пакет объединяет HTTP-транспорт, форматы апдейтов, клавиатуры и отправку медиа.
Он учитывает особенности платформ: буферизацию multipart в прокси, отдельный
CA-бандл MAX и обрезку подписей по границам UTF-16.

## 2. Границы пакета

**Входит**: всё, что знает про HTTP и формат конкретного мессенджера.

**Не входит**: логика диалога, бизнес-сущности и работа с базой данных.

Проверочный критерий: если класс обращается к БД или к бизнес-сущности – ему не место в
пакете.

## 3. Зависимости

```json
{
  "require": {
    "php": ">=8.3",
    "ext-curl": "*",
    "ext-json": "*",
    "psr/log": "^3"
  }
}
```

Пакет не зависит от CMS. Конфигурация передаётся в конструктор обычным объектом, а не
читается из окружения внутри: транспорт не должен знать, откуда взялся токен. Логирование
идёт через PSR-3 `LoggerInterface`, по умолчанию `NullLogger`.


## 4. Структура

```
src/diBot/
  Platform.php              перечисление платформ и фабрика
  Config.php                токен, базовый URL, секрет прокси, CA-бандл, таймауты
  AbstractBotApi.php        транспорт: cURL, JSON и multipart, клавиатуры, лимиты
  AbstractUpdate.php        платформонезависимый апдейт
  AbstractController.php    каркас вебхука и long polling
  Button.php                описание кнопки
  Keyboard.php              сборка клавиатуры с учётом лимитов платформы
  BodyShape.php             логирование формы тела запроса без значений
  Telegram/BotApi.php
  Telegram/Update.php
  Max/BotApi.php
  Max/Update.php
  Outgoing/Media.php        DTO файла: вид, mime, размер, url, локальный путь, подпись
  Outgoing/Policy.php       решение «как отправлять»: по url, загрузкой или отказ
  Outgoing/Decision.php
  Outgoing/Transport.php

```

## 5. Ключевые контракты

### AbstractUpdate

Платформонезависимый апдейт с полями: `updateId`, `platform`, `userId`, `chatId`,
`isPrivateChat`, `text`, `command`, `commandPayload`, `callbackId`, `payload`,
`userProfile` (username, имя, фамилия, язык), `attachments`, `otherContent`, `membership`.

`membership` выставляется только в личном чате, когда собеседник остановил или вернул бота:
`stopped` (Telegram `my_chat_member` – бот был в чате и пропал, MAX `bot_stopped`) или
`started` (не было – появился, MAX `bot_started`). Сравниваются старый и новый статусы;
групповые события не отдаются. `otherContent` – виды содержимого, которое пакет не отдаёт
вложениями (голосовое, видео, стикер и т. п.; содержимое без своего вида – `other`): только
вид, без ссылок на файлы.
Подписка на типы апдейтов – одна константа `UPDATE_TYPES` адаптера на вебхук и polling.

Разбор `/start <payload>` и `/command` делается в базовом классе: deep-link payload
Telegram отдаёт как аргумент команды, и адаптерам про это знать незачем.

### Кнопки

Кнопка описывается платформонезависимо:

```php
Button::callback(string $text, string $payload): self
Button::link(string $text, string $url): self
```

Клавиатура – двумерный массив (ряды на кнопки). Адаптер превращает её в
`reply_markup.inline_keyboard` у Telegram, во вложение `inline_keyboard` у MAX и в quick
replies либо шаблон у Instagram.

Правила оформления кнопок:

- **Роль кнопки отмечается значком в тексте.** Telegram уже поддерживает `style`,
  но общий интерфейс пакета использует значки для одинакового отображения в обеих
  платформах. Платформенные параметры цвета не передаются.
- **Сборка кнопки не имеет права бросать исключение.** Косметика должна стоить голой
  кнопки, а не всего ответа пользователю. Проверка «текст уже начинается с пиктограммы»
  делается таблицей диапазонов кодов, а не через `\p{Extended_Pictographic}`: в сборках
  PCRE2 без этого свойства паттерн не компилируется, а warning
  превращается в исключение и уносит отправку.

### Лимиты платформ

Лимиты объявляются константами адаптера и используются классом `Keyboard` при сборке:
максимум кнопок в ряду и всего, максимальная длина подписи кнопки, длина текста
сообщения, длина подписи к медиа, максимальный размер исходящего файла.

Обрезка текста считается в единицах UTF-16, а не в байтах и не в символах: Telegram
меряет подпись именно так, а разрез между половинами суррогатной пары даёт ошибку 400.

### Отправка файлов

Решение «как отправлять» принимается один раз в `Outgoing\Policy::decide()` и передаётся
в транспорт аргументом: сначала проверяется потолок размера, потом выбирается транспорт –
по URL, загрузкой или отказ.

`Outgoing\Sender` – единственное место, где подтверждённый отказ отправки файла может
деградировать в обычное текстовое сообщение. Сеть, неразобранный ответ, HTTP 5xx,
rate limit и отложенная готовность загруженного медиа пробрасываются приложению;
запасной текст мог бы продублировать уже доставленное сообщение. Медиа приходит туда фабрикой-замыканием, а не готовым объектом:
при отказе ничего даже не строится. Ветка отправки текста при отказе находится вне блока
`try`: исключение внутри неё привело бы к повторной отправке того же сообщения.

При `caption_too_long` отправляется исходный текст с клавиатурой без медиа;
`fallbackText` в этой ветке не используется. Текст обязан помещаться в лимит обычного
сообщения. В остальных ветках `fallbackText` полностью заменяет основной текст и
должен содержать всё, что нельзя потерять. Автоматического разделения отправки на
медиа и отдельный текст нет.

MAX перед любым редактированием читает сообщение. Если `isCaption = false`, наличие
любого вложения кроме клавиатуры вызывает `caption_required` до PUT. Для редактирования
подписи нужен явный `isCaption = true`.

### Вебхук

`AbstractController` даёт готовый обработчик, от платформы требуется реализовать
проверку секрета и разбор апдейта.

Инвариант: **все ветки возвращают 200** – выключенная фича, неверный секрет,
неразобранный апдейт, внутреннее исключение. Пятисотка заставит платформу ретраить по
кругу.

Проверка секрета различается: Telegram шлёт его заголовком
`X-Telegram-Bot-Api-Secret-Token`, MAX – заголовком `X-Max-Bot-Api-Secret`.
При подписке MAX секрет передаётся полем `secret` (5–256 символов `[A-Za-z0-9_-]`);
у Telegram поле `secret_token` допускает 1–256 таких символов. Сравнение в обоих случаях через
`hash_equals`.

### Long polling

Один код на все платформы: снять вебхук, читать апдейты в цикле с таймаутом, отдавать их
обработчику, сохранять позицию. Хранилище позиции подключается снаружи интерфейсом –
пакет не решает, файл это, Redis или таблица.

Если хранилище позиции недоступно, поллинг не запускается вовсе: продолжить с нулевой
позиции значит переобработать всю историю апдейтов заново.

Различие платформ: Telegram считает `offset = последний update_id + 1` и хранит его на
клиенте, MAX отдаёт `marker` сам.

## 6. Особенности адаптеров

### Telegram

Базовый URL берётся из конфигурации: `api.telegram.org` или совместимый прокси,
например Cloudflare Worker. При работе через прокси к запросам добавляется заголовок
`X-Proxy-Auth`. Редиректы не следуются, чтобы секрет не утёк.

Потолок исходящего файла определяется не Telegram, а буфером Worker'а – 8 МБ, рабочий
лимит 7 МБ.

Multipart собирается строкой с явным `Content-Length`, а не через `CURLFile`: Worker
ветвится по этому заголовку, и chunked-запрос попадает в стриминговую ветку, где
отправка документа виснет без кода ошибки.

### MAX

Отдельный CA-бандл с корнем Минцифры через `CURLOPT_CAINFO` – только для API-хоста, не в
системное хранилище. Токен в `Authorization` без `Bearer`.

Отправка файла – три вызова: получить адрес хранилища, залить байты туда (без
`Authorization`, с системным набором сертификатов, через проверку на SSRF), затем
отправить сообщение с полученным токеном. Успех заливки определяется только по HTTP-коду:
тело ответа хранилища ничего не сообщает. Токен приходит либо плоским полем, либо внутри
структуры для изображений – читаются оба варианта.

MAX дообрабатывает файл после ответа хранилища, поэтому отправка сообщения может вернуть
«вложение не готово». Ретраи с нарастающей паузой допустимы **только вне веб-запроса**:
`sleep()` внутри вебхука занимает воркера общего пула.

Признак успеха у MAX другой: поля `ok` в ответе нет, ошибка приходит парой «код плюс
сообщение».

### Instagram

Платформа зарезервирована в перечислении `Platform`; адаптер пока не реализован.

## 7. Версионирование

Пакет распространяется через публичный репозиторий GitHub. Первый релиз ожидает
ревью и слияния PR; опубликованных версий пока нет. После слияния версия выпускается
тегом, приложение подключает её по версии и фиксирует в Composer lock-файле.

## 8. Тесты

В пакете покрываются:

- разбор апдейтов Telegram и MAX в общий формат, включая callback и команды с payload;
- сборка клавиатур под лимиты платформ, обрезка подписей по границам UTF-16;
- `Outgoing\Policy` – выбор транспорта и отказы по размеру и длине подписи;
- срок годности корневых сертификатов в бандле MAX – тест должен начать падать заранее,
  а не в день истечения.

## 9. Контракты реализации

- Зависимости `ext-mbstring` и `ext-openssl` объявлены явно: нужны для UTF-16 и сертификатов.
- Каркас HTTP выделен в `Http/`; подмена `Client` позволяет проверять адаптеры без сети.
- `CursorStore` – внешний контракт. Пакет не выбирает место хранения позиции polling.
- API бросает `ApiException` на отказ; описание ошибки платформы не попадает в исключение.
- Лимит 7 МБ консервативно действует на обе платформы. MIME и размер локального файла
  задаёт приложение; фактический размер повторно проверяется перед загрузкой.
- Кнопки поддерживают опциональный `marked()`. Ошибки украшения не бросаются; неверные
  payload, URL и превышение общего числа кнопок считаются ошибкой вызывающего кода.
- Telegram загружает локальные файлы; MAX также может отправить фотографию по URL.
- Бандл MAX хранится в `resources/` и используется только для стандартного API-хоста.

## 10. Контракты первого релиза

- Polling логирует и пропускает исключение отдельного обработчика. Позиция сохраняется
  после обхода пачки; ошибка хранилища останавливает цикл. Сеть, HTTP 5xx, некорректный JSON и throttling в чтении
  получают до трёх повторов с той же позицией. Подробные интервалы – в README.
- Пустая пачка MAX без `marker` сохраняет текущую позицию; непустая без него отклоняется.
- `MediaNotReadyException` сохраняет вид файла и токен для отложенного `sendFileId()`.
  Сохранение и постановка повтора в очередь выполняются внутри обработчика приложения.
- `Sender::send(fallbackWhenBlocked: false)` запрещает запасной текст при закрытом чате.
  Rate limit и неопределённый результат отправки запрещают его независимо от флага.
- `editMessage()` с null или пустой клавиатурой удаляет кнопки; `isCaption: true`
  сохраняет фото/документы по токену; неизвестные вложения отклоняются до PUT. MAX без текста уведомления не отправляет `answerCallback()` в сеть.
- `ApiException::rateLimitDelay()` отдаёт задержку для воркера; отправка не спит сама.
- `Attachment/` содержит DTO, классификацию фото/документов и ограниченное скачивание.
  Метаданные приходят в `AbstractUpdate::attachments`. Скачивание не зависит от БД,
  очереди или файловой структуры приложения; подробные лимиты и ошибки – в README.

Проверки на живых API и неподтверждённые особенности MAX перечислены в
[ACCEPTANCE.md](ACCEPTANCE.md). `blocked` обозначает запрет доставки, а не доказанное
действие пользователя. Ошибка 403 при отправке медиа не означает, что запрещён текст.
